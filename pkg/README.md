# warthog-fbm

TypeScript bindings for the **Fair Batch Matching (FBM)** engine, the
MEV-proof DeFi matching algorithm at the heart of
[Warthog Network](https://warthog.network/).

The package wraps the WASM build produced by the
[`fair-batch-matching`](https://github.com/warthog-network/fair-batch-matching)
repo. It exposes a strict, hand-typed surface that hides the imprecise
`(a: any) => any` signatures that Embind's `emscripten::val` produces.

## Install

```sh
npm install warthog-fbm
```

## Usage

```ts
import init, { type WarthogFbm } from "warthog-fbm";

const fbm: WarthogFbm = await init();

fbm.editPool({ token: "100", wart: "200" });
fbm.addSell({ price: "1.5", amount: "10" });

const res = fbm.addBuy({ price: "1.5", amount: "5" });

if (res === null) throw new Error("pool unset");
if ("error" in res) throw new Error(res.error);

console.log(res.match.buys);
// [{ amount: "5.00000000", filled: "5.00000000", limit: 1.5 }]
console.log(res.match.toPool);
// null, or { isQuote, base, quote, price }

// Optional-field example — clearAndSetBaseDecimals is the one function
// with a truly optional input. The argument can be omitted entirely.
fbm.clearAndSetBaseDecimals();
fbm.clearAndSetBaseDecimals({ baseDecimals: 8 });
```

## API

All six functions take a strict-typed JS object and return either the
match result or an `{ error }` object. `null` is returned when the pool
has not been set up yet.

| Function | Input | Output | Side effects |
|---|---|---|---|
| `addBuy` | `{ price, amount }` (str, str) | `MatchResponse \| null` | inserts a buy order |
| `addSell` | `{ price, amount }` (str, str) | `MatchResponse \| null` | inserts a sell order |
| `editPool` | `{ token, wart }` (str, str) | `MatchResponse \| null` | updates pool reserves |
| `deleteOrder` | `{ base, index }` (bool, num) | `MatchResponse \| null` | removes one order |
| `setFee` | `{ E4 }` (num, 0–9999) | `MatchResponse \| null` | updates pool fee |
| `clearAndSetBaseDecimals` | `{ baseDecimals? }` (num, 0–18, **optional**) | `MatchResponse \| null` | resets book + pool |

The success shape mirrors the C++ `wasm_callbacks.cpp` `match_result()` output:

```ts
type MatchResponse =
  | { match: MatchResult }
  | { error: string }
  | null;

interface MatchResult {
  buys:        Array<{ amount: string; filled: string; limit: number }>;
  sells:       Array<{ amount: string; filled: string; limit: number }>;
  poolBefore:  { base: string; quote: string; price: number };
  poolAfter:   { base: string; quote: string; price: number };
  toPool:      { isQuote: boolean; base: string; quote: string; price: number } | null;
  filled: {
    outBaseSeller: string; inQuoteSeller: string; priceSeller: number;
    outQuoteBuyer: string; inBaseBuyer:   string; priceBuyer:  number;
  };
  matched:     { base: string; quote: string; price: number | null };
}
```

## How the types are built

This package uses a **two-file declaration architecture**:

1. `index.raw.d.ts` — auto-generated by `emcc --emit-tsd`. Reflects the
   Embind bindings verbatim; every function signature is `(a: any) => any`.
2. `index.d.ts` — handwritten public types. Imports `MainModule` from
   `index.raw`, uses `Omit<MainModule, ...>` to slice away the imprecise
   signatures, and re-adds them with strict interfaces. The single
   optional field (`baseDecimals?`) is enforced only on
   `clearAndSetBaseDecimals`, the one function whose C++ side accepts a
   missing key.

This way `tsc` never regenerates the hand-curated public surface, but
type drift between the C++ Embind bindings and the TS wrapper is caught
at compile time.

## Wasm loading

`fbm.wasm` is fetched relative to the loader module. The default
`locateFile` keeps it next to `fbm.js`, which is where bundlers
(Vite, webpack, esbuild, Bun) and plain `<script type="module">` setups
both expect it. To override the URL, pass `locateFile`:

```ts
const fbm = await init({
  locateFile: (path, prefix) => `https://cdn.example.com/${path}`,
});
```
